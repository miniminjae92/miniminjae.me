# Living Personal Site

## 목적

이 사이트의 첫 임무는 강민재가 어떤 사람인지 이해시키는 것이다.

방문 흐름은 다음 질문에 차례로 답한다.

1. 이 사람은 누구인가?
2. 무엇을 만들었는가?
3. 무엇을 생각하고 기록하는가?

## 방향 — 페이지별 표현, 공통 디테일 문법 (ADR-0002)

페이지들을 하나의 은유나 좌표계로 묶지 않는다. 각 페이지는 자기 성격을
가장 잘 표현하는 레이아웃을 가진다.

- **홈** — 3초 버전. 주장(카피)과 증거로 가는 입구만 놓는다.
- **/about** — 3분 버전. 이력서형: 헤더 밴드 + 단일 그리드 6섹션.
  이 경계를 정하지 않으면 /about 이 홈의 복사본이 된다.
- **/writing** — 아카이브. 주인공은 목록의 밀도다. 헤더는 한 문장만 말하고
  물러난다.
- **/portfolio (Projects)** — 증거. 항목 하나하나가 문제·판단·결과로 이어지는
  입구다.
- **글 상세** — 읽기 편한 편집 디자인이 전부다.

사이트를 하나로 묶는 것은 /about 에서 확립된 디테일 문법이다.

- 구획은 1px 헤어라인(`border`)만 쓴다. 배경 전환·카드·그림자를 쓰지 않는다.
- 섹션 제목은 영문 단독 `text-xl`, 페이지 제목은 `text-2xl`. 한글 병기는
  제목을 캡션으로 만든다.
- 날짜는 점 표기(`yyyy. MM. dd.`) + `tabular-nums`.
- 형제를 흐리는 리스트 호버가 시그니처 인터랙션이다.
- 같은 정보를 한 화면에서 반복하지 않는다(카운트·소셜 링크 등).

## 정보 구조

최상위는 셋이다. Roots는 별도 영역이 아니라 Projects 항목으로 다룬다(ADR-0001).

```text
/about       About — 자기소개, 현재의 관심, 일하는 관점, 해온 일
/portfolio   Projects — 문제, 판단, 결과, 관련 Writing의 연결
             ├─ Agent OS      visibility: private
             ├─ dref          visibility: private
             └─ minjae.log    visibility: public
/writing     Writing — Understand / Solve / Reflect 렌즈
```

글의 permalink는 `/insight/:slug`, `/memo/:slug`, `/log/:slug` 그대로다.
Lens는 라벨로만 덧입혔고 URL을 옮기지 않았다. 인덱스 3개만 `/writing`으로
308한다. `/portfolio` URL도 유지한다 — Projects는 라벨 교체이지 이주가 아니다.

홈의 섹션 순서는 `주장 → Projects → Writing`이다. 주장 다음에는 증거가 와야
하고, 홈이 이미 글 목록이라 Writing을 앞에 두면 Projects가 스크롤 아래로
묻힌다. Agent OS나 dref는 첫 화면의 주인공이 아니다.

## 공개와 비공개의 경계

```text
Public
├─ Root System의 추상적 이름 또는 역할
├─ “private” 상태
└─ 공개 가능한 제작 사례

Private
├─ 실제 Private Interface
├─ 운영 상태와 개인 데이터
├─ 내부 주소와 접근 정책
└─ 변경·실행 기능
```

- 공개하는 것: 어떤 문제를 풀었나, 무엇을 버렸나, 무엇이 달라졌나, 관련 기록.
- 공개하지 않는 것: 실시간 상태, 세션 제목, 로컬 경로, 접속 주소, 사용량,
  비용, 계정 정보.
- 링크 목록이 비어 있는 것이 정상 상태다. 빈 링크 행 대신
  “비공개 시스템 · 소스 미공개”를 표시한다.
- 공개 사이트에서 Private Interface를 iframe으로 삽입하거나 API로 호출하지
  않는다.

Private Interface는 추후 Tailscale Serve로 제공할 수 있다. 서비스는
localhost에만 바인딩하고, Funnel은 사용하지 않으며, 접근 정책과
애플리케이션 양쪽에서 소유자만 허용한다. 공개 사이트에는 실제 `.ts.net`
주소를 넣지 않고 개인 북마크를 진입점으로 사용한다.

## 보안 원칙

- 시각적 표현은 인증 수단이 아니다.
- 숨겨진 링크, 키보드 단축키, 난해한 URL을 접근 제어로 간주하지 않는다.
- 공개 번들, HTML, 메타데이터에 private 호스트명이나 토큰을 포함하지 않는다.
- Private Interface는 읽기 전용 화면이라도 별도의 네트워크 접근 제어를
  적용한다.

## 시각 원칙

- 한국어 카피가 장식보다 먼저 읽혀야 한다.
- 모션은 의미를 설명할 때만 사용한다. `prefers-reduced-motion` 환경에서는
  장식 애니메이션을 제거한다.

## 시각화에 대한 판정

실데이터 기준(글 18편, 고유 태그 8개, `프리코스` 태그 하나가 8편)으로 다음은
**만들지 않는다.**

- **관계 그래프** — 노드가 모자라 "연결된 작업이 없다"를 정확하게 시각화한다
- **월별 활동 밀도 스트립** — 18개월 중 8개월이 공백이다
- **스킬 게이지, 레벨 바** — 분모가 없다

살아남는 것은 **시간축** 하나다. 날짜는 모든 항목에 있고 스키마로 검증되고
쓸수록 좋아지며 절대 비지 않는다. 결과 수치는 차트 라이브러리 없이 `<dl>` +
`→` 델타로 표현하고, 조건이나 분모를 못 적는 수치는 싣지 않는다.
