# Living Personal Site

## 목적

이 사이트의 첫 임무는 세계관을 보여주는 것이 아니라 강민재가 어떤 사람인지 이해시키는 것이다. 세계수, 도서관, 우주 같은 장치는 자기소개와 공개 작업 사이의 관계를 기억하게 만드는 시각 언어로 사용한다.

방문 흐름은 다음 질문에 차례로 답한다.

1. 이 사람은 누구인가?
2. 무엇을 생각하고 기록하는가?
3. 무엇을 만들었는가?
4. 그 활동을 무엇이 지속시키는가?

## 정보 구조

최상위는 셋이다. Roots는 별도 영역이 아니라 Portfolio 항목으로 다룬다(ADR-0001).

```text
/about       About
             └─ 자기소개, 현재의 관심, 일하는 관점, 해온 일

/portfolio   Portfolio
             └─ Constellation — 문제, 판단, 결과, 관련 Writing의 연결
                ├─ Agent OS      visibility: private
                ├─ dref          visibility: private
                └─ minjae.log    visibility: public

/writing     Writing
             ├─ Understand — 개념과 구조를 이해시키는 글
             ├─ Solve — 문제와 해결 과정을 재사용하게 하는 글
             └─ Reflect — 경험에서 얻은 판단과 다음 질문
```

글의 permalink는 `/insight/:slug`, `/memo/:slug`, `/log/:slug` 그대로다. Lens는 라벨로만 덧입혔고 URL을 옮기지 않았다. 인덱스 3개만 `/writing`으로 308한다.

## 화면 서사

홈의 섹션 순서는 `About → Portfolio → Writing → 연락`이다. 주장 다음에는 증거가 와야 하고, 홈이 이미 글 목록이라 Writing을 두 번째에 두면 Portfolio가 스크롤 아래로 묻힌다.

홈은 3초 버전(주장 + 증거로 가는 링크), `/about`은 3분 버전(증거)이다. 이 경계를 정하지 않으면 `/about`이 홈의 복사본이 된다.

### 1. 첫 화면 — About

- 가장 큰 카피는 이름이나 역할 나열보다 “무엇을 이해하고 무엇으로 만드는 사람인가”를 말한다.
- 세계수는 일러스트로 그리지 않는다. 레일이 그 역할을 한다.
- 주요 행동은 `자기소개 전문 보기`, `만든 것 보기`, `글 읽기`다.
- Agent OS나 dref는 첫 화면의 주인공이 아니다.

### 2. 나무 — Writing

- 가지는 `Understand`, `Solve`, `Reflect`라는 Writing Lens다.
- 잎은 개별 글이다.
- Lens는 글의 형식이 아니라 독자에게 제공하는 주된 가치다.
- 글 상세 화면은 세계관보다 읽기 편한 편집 디자인을 우선한다.

### 3. 하늘 — Portfolio

- Portfolio 항목 하나를 고립된 별이 아니라 Constellation으로 표현한다.
- 각 Constellation은 문제, 핵심 판단, 결과, 저장소, 관련 Writing을 연결할 수 있다.
- 탐색 화면은 시각적일 수 있지만 실제 사례 페이지는 명확하고 읽기 쉬워야 한다.

### 4. 뿌리 — Roots는 Portfolio 안에 있다

- Roots를 별도 화면으로 만들지 않는다(ADR-0001). Agent OS와 dref는 `visibility: private`인 Portfolio 항목이다.
- 공개하는 것: 어떤 문제를 풀었나, 무엇을 버렸나, 무엇이 달라졌나, 관련 기록.
- 공개하지 않는 것: 실시간 상태, 세션 제목, 로컬 경로, 접속 주소, 사용량, 비용, 계정 정보.
- 링크 목록이 비어 있는 것이 정상 상태다. 빈 링크 행 대신 “비공개 시스템 · 소스 미공개”를 표시한다.
- 공개 사이트에서 Private Interface를 iframe으로 삽입하거나 API로 호출하지 않는다.

## 공개와 비공개의 경계

```text
Public
├─ Root System의 추상적 이름 또는 역할
├─ “private” 상태
└─ 공개 가능한 제작 사례

Private
├─ 실제 Private Interface
├─ 운영 상태와 개인 데이터
├─ 내부 주소와 접근 정책
└─ 변경·실행 기능
```

Private Interface는 추후 Tailscale Serve로 제공할 수 있다. 서비스는 localhost에만 바인딩하고, Funnel은 사용하지 않으며, 접근 정책과 애플리케이션 양쪽에서 소유자만 허용한다. 공개 사이트에는 실제 `.ts.net` 주소를 넣지 않고 개인 북마크를 진입점으로 사용한다.

## 시각 원칙

- 한국어 자기소개 카피가 장식보다 먼저 읽혀야 한다.
- 모션은 성장, 연결, 호흡을 설명할 때만 사용한다.
- 세계수는 하나의 거대한 일러스트보다 페이지 전체를 연결하는 구조로 사용한다.
- 마법의 도서관은 Writing의 Archive 표현으로 제한한다.
- 우주는 Portfolio의 관계와 확장을 표현한다.
- 모바일에서는 레일의 세로선만 살리고 거터 라벨을 본문 위 인라인으로 내린다. 세로 흐름 `About → Portfolio → Writing → 연락`은 데스크톱과 같다.
- `prefers-reduced-motion` 환경에서는 장식 애니메이션을 제거한다.

## 보안 원칙

- Roots의 시각적 표현은 인증 수단이 아니다.
- 숨겨진 링크, 키보드 단축키, 난해한 URL을 접근 제어로 간주하지 않는다.
- 공개 번들, HTML, 메타데이터에 private 호스트명이나 토큰을 포함하지 않는다.
- Private Interface는 읽기 전용 화면이라도 별도의 네트워크 접근 제어를 적용한다.

## 채택한 시각 방향 — 등뼈(Rail)

2026-07-25 세션의 프로토타입 6종(`Living Portrait` / `Editorial Descent` / `Celestial Atlas`, `Living Canopy` / `Grand Library` / `Root & Rune`)은 **전부 거절됐고 삭제됐다.** 손으로 그린 세계수 SVG, 장식 키프레임, 디자인 시스템을 무시한 자체 팔레트가 공통 원인이었다. 되살리지 않는다.

거절의 진짜 원인은 시각 방향이 아니라 **순서**였다. 포트폴리오 항목이 하나도 없는 상태에서 11개 용어와 4단계 IA를 먼저 정했고, 프로토타입은 존재하지 않는 글 제목으로 채워졌다. 가상의 사람에 대한 페이지를 평가한 셈이다.

채택한 방향은 하나다.

> **세계수를 그리지 않고, 세계수를 레이아웃으로 만든다.**

고정 x좌표의 세로 1px 레일이 사이트를 관통한다. 왼쪽 거터에는 섹션 라벨, 연도, 날짜 같은 **좌표만** 놓이고 오른쪽에 본문이 붙는다. 섹션 사이에 구분선이나 배경 전환을 넣지 않는다. 레일은 끊기지 않고 거터 라벨만 바뀐다. 라우트가 나뉘어도 좌표계가 그대로라 하나의 사이트로 읽힌다.

새로 발명한 것이 아니라 기존 모티프의 승격이다. `category-links`가 이미 L자 규칙선을, `post-archive-list`가 이미 거터 연도 라벨을 쓰고 있었다.

거터 폭 `--rail-gutter: 8.5rem`은 임의값이 아니다. 50rem 셸에서 좌우 여백과 본문 38rem을 빼면 남는 값이다.

**레일을 쓰지 않는 곳**: 글 상세 페이지. 좌표가 날짜 하나뿐이라 거터 136px이 빈 여백으로 읽힌다. 실제로 적용해 보고 판정했다.

## 시각화에 대한 판정

실데이터 기준(글 18편, 고유 태그 8개, `프리코스` 태그 하나가 8편)으로 다음은 **만들지 않는다.**

- **관계 그래프** — 노드가 모자라 "연결된 작업이 없다"를 정확하게 시각화한다
- **월별 활동 밀도 스트립** — 18개월 중 8개월이 공백이다
- **스킬 게이지, 레벨 바** — 분모가 없다

살아남는 것은 **시간축** 하나다. 날짜는 모든 항목에 있고 스키마로 검증되고 쓸수록 좋아지며 절대 비지 않는다. 결과 수치는 차트 라이브러리 없이 `<dl>` + `→` 델타로 표현하고, 조건이나 분모를 못 적는 수치는 싣지 않는다.

## 아직 하지 않은 것

- 실제 Agent OS 또는 dref 연결
- 인증과 Tailscale 설정
- 글 URL 마이그레이션(`/insight/:slug` → `/writing/:slug`) — 렌즈는 라벨로만 덧입혔다
- 커스텀 도메인 연결
