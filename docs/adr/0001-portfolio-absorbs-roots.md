# ADR-0001: Portfolio가 Roots를 흡수한다

- 날짜: 2026-08-02
- 상태: accepted

## 배경

`CONTEXT.md`는 최상위 영역을 넷으로 정의했다.

- **Portfolio** — 세상에 내놓은 작업과 그 작업이 만든 변화를 설명하는 공개 결과 영역
- **Roots** — 공개 활동을 지속시키는 비공개 기반 시스템들의 영역. 공개 사이트에서는 존재와 의미만 표현한다

이 구분은 포트폴리오 항목이 하나도 없는 상태에서 만들어졌다. 그래서 Portfolio에 무엇이 들어갈지 정하지 않은 채 Roots를 "공개하지 않는 것"으로 먼저 규정했다.

2026-08-02, 포트폴리오로 내세울 실체를 정하는 과정에서 그 답이 **Agent OS, dref, 이 블로그**로 나왔다. 앞의 둘은 `CONTEXT.md`가 Roots로 분류해 둔 바로 그 시스템들이다. 정의대로라면 존재와 의미만 언급하고 끝내야 하는데, 그러면 내세울 게 블로그 하나만 남는다.

## 결정

**Portfolio가 Roots를 흡수한다. Roots를 별도의 최상위 영역으로 만들지 않는다.**

경계는 영역이 아니라 항목 안에서 긋는다.

- **공개한다** — 어떤 문제를 풀었나, 어떤 트레이드오프로 무엇을 버렸나, 무엇이 달라졌나, 관련 기록
- **공개하지 않는다** — 접속 주소, 세션 로그, 로컬 경로, 비용과 사용량, 계정 정보, 운영 상태

각 Portfolio 항목은 `visibility: "public" | "private"` 필드를 갖는다. `private`이면 소스와 인터페이스가 비공개라는 뜻이고, 링크 목록이 비어 있는 것이 정상 상태다. UI는 빈 링크 행 대신 "비공개 시스템 · 소스 미공개"를 표시한다.

## 근거

- **시스템의 인터페이스와 설계는 다른 것이다.** 비공개인 것은 접근 경로와 데이터이지 판단이 아니다. 사용자가 이미 `agent-os/DECISIONS.md`로 결정을 기록해 왔으므로 케이스 스터디의 원자재가 이미 존재한다.
- **최상위가 셋으로 줄어든다.** About / Portfolio / Writing. 사용자가 요청한 "세 가지"와 정확히 맞는다. 넷째 영역은 앞의 셋을 희석시킨다.
- **Roots 단독 페이지는 사이트에서 가장 약한 페이지가 된다.** 정의상 "이런 것들이 존재합니다" 세 줄이 전부다. 게다가 설계 문서가 그 지점을 최고 위험 구간(호스트명·경로 유출)으로 지목하고 있다.
- **보안 원칙은 그대로 유지된다.** 영역을 합친 것이지 공개 범위를 넓힌 것이 아니다.

## 버린 선택지

- **Roots를 별도 영역으로 유지** — 원안. 최상위가 넷이 되고 그중 하나가 실질적으로 빈 페이지가 된다.
- **Agent OS와 dref를 포트폴리오에서 제외** — 그러면 포트폴리오에 블로그 하나만 남는다. 우테코 미션 회고를 넣는 선택지도 있었으나, 변별력이 낮다(같은 과정을 거친 모든 지원자가 갖고 있다).

## 영향

- `CONTEXT.md`의 Roots, Root System, Living Tree 항목을 갱신한다.
- `docs/design/living-personal-site.md`의 IA `About → Writing → Portfolio → Roots`가 `About → Portfolio → Writing`으로 바뀐다.
- `src/config/navigation.ts`가 최상위 셋만 노출한다.
- velite `projects` 컬렉션에 `visibility` 필드가 생긴다.

## 되돌리는 법

Roots에 공개 가능한 산출물이 생기면(dref 오픈소스화, Agent OS 공개 글 등) 다시 볼 수 있다. 그때는 별도 영역이 아니라 Portfolio 항목의 `visibility`를 `public`으로 바꾸는 것이 먼저다.
